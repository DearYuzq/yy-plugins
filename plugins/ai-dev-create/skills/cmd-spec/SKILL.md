# /ai-dev-create:spec - 创建功能规范

创建详细的功能规范文档，定义需求、验收标准和技术约束。

## 使用方式

```bash
/ai-dev-create:spec "功能描述"
/ai-dev-create:spec "添加用户认证功能"
/ai-dev-create:spec --template user-story
/ai-dev-create:spec --skip-clarify    # 跳过澄清阶段（当需求非常明确时）
```

## 参数说明

| 参数 | 说明 |
|------|------|
| `"功能描述"` | 功能需求描述 |
| `--template` | 使用特定模板 |
| `--skip-clarify` | 跳过澄清阶段 |

## 输出

生成 `.claude/specs/[feature-name].md` 规范文档。

---

## 流程

### Phase 0: 清晰度检查（新增）

```
Step 1: 解析用户输入
  ├── 提取名词（实体）
  ├── 提取动词（动作）
  ├── 提取形容词/副词（约束）
  └── 识别技术术语

Step 2: 计算清晰度评分

Step 3: 决策分支
  IF 清晰度 < 0.7:
    → 调用 clarifier agent
    → 等待澄清完成
    → 重新计算清晰度

  IF 清晰度仍 < 0.7:
    → 提示用户："需求仍不清晰，建议人工澄清"
    → 记录需要澄清的问题列表
    → 暂停流程

  IF 清晰度 ≥ 0.7:
    → 继续 Phase 1
```

### Phase 1: 初始理解（自动）

```
输入：用户需求 + 澄清文档（如有）

动作：
  1. 显示解析的实体和动作
  2. 展示检测到的技术栈
  3. 列出潜在模糊点

输出：初始理解摘要
```

**示例输出**：

```markdown
## 初始理解

**解析自**："添加用户 OAuth 认证"

**检测到的实体**：
- User（现有实体）
- Authentication（新概念）
- OAuth（外部服务）

**检测到的动作**：
- 用户登录
- 用户登出
- OAuth 认证

**模糊点**：
1. 哪些 OAuth 提供商？（Google、GitHub、Facebook 等）
2. 是否需要传统邮箱/密码登录？
3. 存储哪些用户数据？

**清晰度评分**：0.65（需要澄清）
```

### Phase 2: 交互澄清（条件触发）

**触发条件**：
- 清晰度评分 < 0.8
- 使用 `--interactive` 标志
- 检测到关键模糊点

**澄清格式**：

```markdown
## 澄清问题 1/3

**问题**：您需要支持哪些 OAuth 提供商？

选项：
A) 仅 Google
B) 仅 GitHub
C) Google 和 GitHub
D) 其他（请说明）

您的选择：_
```

**澄清完成**：

```markdown
## 澄清总结

基于您的回答：
- OAuth 提供商：Google 和 GitHub
- 传统认证：保留邮箱/密码作为备选
- 存储数据：邮箱、姓名、头像 URL

**清晰度评分**：0.92（可生成规范）

是否继续生成规范？[Y/n]
```

### Phase 3: 规范生成

**生成内容**：
- 用户故事（来自确认的动作）
- 功能需求（来自确认的实体/动作）
- 验收标准（来自确认的行为）
- 边界情况（来自澄清的问题）

### Phase 4: 审查确认

**最终审查**：

```markdown
## 规范审查

生成的规范：`.claude/specs/user-oauth-auth.md`

请确认：
- [ ] 用户故事准确反映需求
- [ ] 所有澄清的需求已捕获
- [ ] 验收标准可测试
- [ ] 无遗漏边界情况

输入 'confirm' 继续，或提供反馈：_
```

## 问题模板

### 实体澄清

```
问题：您提到的 '{实体名}' 具体指什么？

选项：
A) {选项A} - {描述}
B) {选项B} - {描述}
C) {选项C} - {描述}
D) 其他（请说明）
```

### 动作澄清

```
问题：'{动作}' 应该在什么情况下触发？

选项：
A) 用户主动触发
B) 系统自动触发
C) 外部事件触发
D) 其他
```

### 边界澄清

```
问题：'{功能}' 是否需要处理以下边界情况？

多选：
- [ ] 空输入
- [ ] 超大输入
- [ ] 并发访问
- [ ] 网络异常
```

## Agent 调用

本命令需要调用以下 Agent：

### 调用的 Agent

| Agent | 调用时机 | 输入 | 输出 |
|-------|----------|------|------|
| clarifier | 清晰度 < 0.7 时 | 用户需求 | 澄清文档 |
| planner | 规范生成时 | 需求 + 澄清文档 | 规范文档 |

### 调用方式

#### 清晰度不足时调用 clarifier agent

```
Agent 工具参数：
- subagent_type: "clarifier"
- description: "需求澄清"
- prompt: "澄清以下需求，使用选项式问题：
  用户需求：{用户输入}
  模糊点：{检测到的模糊点列表}
  输出澄清文档到：.claude/clarifications/{feature}/"
```

#### 调用 planner agent 生成规范

```
Agent 工具参数：
- subagent_type: "planner"
- description: "创建功能规范"
- prompt: "基于以下内容创建功能规范：
  需求：{用户需求}
  澄清文档：{澄清文档路径（如有）}
  输出规范到：.claude/specs/{feature}.md"
```

### 上下文传递

**接收的上下文**：
- 用户需求描述
- 澄清文档路径（如已澄清）

**输出的上下文**：
- 规范文档路径：`.claude/specs/{feature}.md`
- 用户故事列表
- 验收标准列表
- 技术约束列表

### 执行流程

1. 解析用户输入
2. 计算清晰度评分
3. IF 清晰度 < 0.7:
   - 使用 Agent 工具调用 clarifier agent
   - 等待澄清完成
4. 使用 Agent 工具调用 planner agent
5. 等待规范生成
6. 显示规范摘要，请求用户确认
7. 保存规范到 `.claude/specs/{feature}.md`
