# 子智能体策略

## 使用原则

- 频繁使用子智能体，保持主上下文窗口简洁
- 将调研、探索、并行分析等工作交给子智能体处理
- 复杂问题通过子智能体增加算力投入
- 每个子智能体只分配一个任务，确保专注执行

## Agent 设计规范

给 Agent **非常具体的职责和返回格式**，否则它会自作主张改了一堆东西但不告诉你改了啥。

设计原则：

- 每个 Agent 只负责一件事
- 明确规定返回格式（如 JSON、markdown 表格）
- 限定可用工具范围，防止越权
- 设置 `allowed-tools` 限制操作边界

## 常见 Agent 类型

- 代码架构审查
- 构建错误修复
- 战略计划架构师
- UX 设计修复
- 文档架构师

## 加载时机

**必须场景**：
- 任务涉及多个文件修改
- 需要调研或探索代码库
- 设计新的 Agent 或 Skill
- 并行处理多个子任务
